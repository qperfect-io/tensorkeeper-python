    API Reference¶

    The public surface is small: one simulator and its GPU variant, one state, and the methods on them. Everything else comes from mimiqcircuits. For how to use these rather than what they are, start with Getting Started.

    TkSimulator is a mimiqcircuits.backends.LocalBackend. The interface's abstract members are name, version, capabilities, build_state, compile and evolve; execute is inherited from LocalBackend and built on the last three. compile is pure: no RNG and no sampling, so one compiled circuit serves every shot and every trajectory of a run.

    Bitstring ordering

    BitString("01") sets qubit 0 to 0 and qubit 1 to 1. The leftmost character is qubit 0. This is the MIMIQ convention, and it is the reverse of Qiskit's.

    Bond dimension

    TkState.bond_dim and the BondDim instruction report the bond dimension of the residual MPS, not of the physical state. A maximally entangled stabilizer state reads back as 1, because its entanglement is in the Clifford frame. See Concepts.

    Simulator¶

    tensorkeeper.TkSimulator ¶

    Bases: LocalBackend

    Clifford-augmented MPS quantum circuit simulator.

    The state is held as |psi> = C |phi>: a Clifford frame C tracked as a stabilizer tableau, and a matrix product state |phi>, the residual, carrying only the nonstabilizerness entanglement. Clifford gates and Pauli noise are absorbed by the frame at O(n) and cost no bond dimension, so a circuit that is mostly Clifford stays cheap however deep and however wide it is. Non-Clifford gates go to the MPS as dressed gates, and they are what you pay for.

    The cost model. Bond dimension in |phi> grows with the magic in the circuit, the number and placement of non-Clifford gates, and not with the circuit's depth or with the entanglement of |psi>. That makes this the right simulator for Clifford-dominated workloads (Clifford+T, magic state cultivation, error correction) and the wrong one for circuits whose difficulty is spread everywhere, where it does an ordinary MPS simulator's work and pays a little extra to carry the frame.

    Two consequences to absorb before reading any number this backend reports:

    • :attr:.TkState.bond_dim and the BondDim instruction describe |phi>, not |psi>. A maximally entangled stabilizer state reads back as 1. It is the number that governs cost; it is not an entanglement measure.
    • The first few non-Clifford gates on a wide register are usually free. Optimization-free disentangling applies a rotation as a single-qubit gate whenever it can find a qubit where |phi> is still a product state, so bond dimension typically stays at 1 until roughly the register's worth of magic has accumulated, and only then starts to climb.

    Usage. There are two entry points, and they do different things:

    • :meth:execute is the MIMIQ driver, inherited from :class:~mimiqcircuits.backends.LocalBackend. It runs the pass pipeline, decides between sampling and trajectory mode, evolves, samples, and hands back :class:~mimiqcircuits.QCSResults. This is what you want almost always.
    • :meth:build_state / :meth:compile / :meth:evolve are the three primitives execute is built from. Drive them yourself when you want one evolution and then many non-destructive queries against the resulting :class:.TkState.

    Qubit and classical-bit indices are 0-based, as in mimiqcircuits.

    Configuration is construction-only: build a new simulator to change a knob rather than overriding it per call, which keeps the execute keyword surface free of sentinel-versus-explicit collisions.

    Parameters:

    Name Type Description Default
    bonddim int

    Maximum bond dimension for the residual MPS, and the value advertised as limits().max_bond_dim. This is the accuracy knob: once the residual would need more than bonddim, compression starts discarding weight and the reported fidelity drops below 1. The default of 256 is comfortable for most Clifford-dominated circuits. It caps |phi>, so a circuit with little magic never approaches it whatever |psi> looks like. Raise it when the fidelity comes back low; lower it to trade accuracy for speed and memory on a deliberately approximate run. Must be positive: limits() has to advertise a positive integer, so a non-positive cap is refused at construction rather than surfacing later as an invalid advertisement.

    		 256
    sv_cutoff Optional[float]

    Singular values below this fraction of the largest one are discarded during compression, regardless of bonddim. Defaults to :data:DEFAULT_SV_CUTOFF (1e-8), small enough to be numerical hygiene rather than approximation. Raise it (1e-4, 1e-3) to trade a controlled amount of fidelity for a smaller bond dimension on a circuit that is too big at the cutoff you have. It is the gentler of the two truncation knobs, because it drops weight that is genuinely small instead of whatever does not fit. Leave it alone for exact work.

    		 None
    disentangle_period int | str

    How often to run the Clifford disentangler, measured in MPS-touching operations. The disentangler looks for a two-qubit Clifford at each cut that lowers the entropy there, applies it to the MPS and compensates it in the frame. That is an exact re-split of C against |phi>, and it recovers bond dimension which earlier operations left in the residual as gauge rather than magic.

    A positive integer N sweeps every N operations; the default, 1, sweeps after each one. "auto" adapts: it sweeps after an operation that grew the bond dimension, the period doubles whenever a sweep fails to reduce it, and resets as soon as one succeeds. 0 disables it.

    Keeping the bond dimension low makes every later MPS operation cheaper, since their cost grows as its cube, so the sweeps usually pay for themselves: on msc_d5_noisy a shot is 7x faster with 1 than with 0. Turn it off only for a circuit that never accumulates gauge entanglement. Since it is exact, it can never change the answer on a run that was not truncating.

    		 1
    max_num_threads Optional[int]

    The most threads a run of this simulator uses, for the linear algebra and for sampling alike. None (default) leaves both to the process setting (the MIMIQ_* thread variables). The cap is held for the length of each :meth:execute and :meth:evolve call and released after, so it never outlives the run. The thread counts are process-wide: simulators running at the same time on different Python threads share them, and each runs at the smallest cap any of them holds.

    		 None
    linalg Optional[str]

    The linear algebra library the residual MPS runs on: "openblas", "mkl" or "faer". None (default) takes whichever engine this installation ships, preferring OpenBLAS, which the wheel bundles. The Windows wheel has no OpenBLAS engine, so there the default is MKL. "mkl" is Intel MKL, whose runtime comes from the mkl package the wheel depends on. "faer" is a pure-Rust library with no system dependency, usually the slowest of the three. Results agree across engines to rounding. A named engine the installation lacks raises :class:ImportError at the first state, rather than switching engine. The resolved name is readable as sim.linalg; :func:tensorkeeper.available_engines lists what is installed.

    		 None

    Raises:

    Type Description
    ValueError

    If bonddim is not positive, max_num_threads is below 1, or linalg is not an engine name.
    RuntimeError

    On the public kernel-free build, where only :class:~tensorkeeper.MockTensorKeeper runs.

    Examples:

    A deep, wide Clifford circuit produces a highly entangled state and
costs nothing:

>>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> sim = TkSimulator(bonddim=128)
>>> c = mc.Circuit()
>>> for _ in range(50):
...     for q in range(40):
...         _ = c.push(mc.GateH(), q)
...     for q in range(39):
...         _ = c.push(mc.GateCX(), q, q + 1)
>>> state, fidelity = sim.evolve(sim.build_state(40), sim.compile(c))
>>> len(c), state.bond_dim
(3950, 1)
>>> type(fidelity).__name__
'ExactFidelity'

The same circuit on a plain MPS simulator would need a bond dimension of
up to ``2**20`` to stay exact.

Driving it through ``execute`` instead, with measurements and shots:

>>> c = mc.Circuit()
>>> _ = c.push(mc.GateH(), 0)
>>> _ = c.push(mc.GateCX(), 0, 1)
>>> _ = c.push(mc.Measure(), 0, 0)
>>> _ = c.push(mc.Measure(), 1, 1)
>>> results = TkSimulator().execute(c, nsamples=100, seed=42)
>>> sorted(bs.to01() for bs in results.histogram())
['00', '11']
>>> sum(results.histogram().values())
100

    can_handle(circuit) ¶

    Decline up front what evolve would refuse mid-circuit.

    The default check reads the capability set, which is too coarse in two places. Declaring noise admits any Kraus channel, while a Clifford frame can only absorb the mixed-unitary (Pauli) ones: amplitude damping is not a Pauli mixture, so there is nothing to sample into the frame. And a handful of operations belong to no capability token at all, so nothing gates them.

    Both would otherwise surface as an opaque failure part-way through a long circuit rather than an admission error before any work is done. Anything this accepts is then subject to the inherited capability check.

    Parameters:

    Name Type Description Default
    circuit Circuit

    The circuit to admit or decline. Only inspected, never modified, and only the first offending operation is reported.

    		 required

    Returns:

    Name Type Description
    An AdmissionResult

    class:~mimiqcircuits.backends.Admissible verdict, or an
    AdmissionResult

    class:~mimiqcircuits.backends.Inadmissible one carrying a
    AdmissionResult

    reason that names the offending operation.

    Examples:

    >>> import mimiqcircuits as mc
>>> from mimiqcircuits.backends import Inadmissible, is_admissible
>>> from tensorkeeper import TkSimulator
>>> sim = TkSimulator()
>>> ok = mc.Circuit()
>>> _ = ok.push(mc.GateH(), 0)
>>> _ = ok.push(mc.Depolarizing1(0.1), 0)
>>> is_admissible(sim.can_handle(ok))
True

Amplitude damping is a Kraus channel but not a Pauli mixture, so it
is declined before any work is done:

>>> bad = mc.Circuit()
>>> _ = bad.push(mc.AmplitudeDamping(0.1), 0)
>>> verdict = sim.can_handle(bad)
>>> isinstance(verdict, Inadmissible)
True
>>> "mixed-unitary" in verdict.reason
True

    compile(circuit) ¶

    Compile a circuit into a form :meth:evolve can run.

    Pure, as the interface requires: no RNG, no sampling, no state, and no dependence on anything but circuit. All the real work is per-instruction dispatch that depends on the current Clifford frame, and the frame does not exist until evolution starts (a dressed gate's support is a function of everything before it), so the artifact is mostly a wrapper. It expands containers (GateCall, Block, BlockCall) into the instructions they hold, so a Clifford inside one still goes to the frame. What it adds is a table of the parts that depend on an operation alone (a noise channel's branches, a gate's matrix), filled on first use. The purity is what lets one compiled artifact, and so one table, serve every trajectory (see :meth:recompile_per_trajectory).

    Parameters:

    Name Type Description Default
    circuit Circuit

    The circuit to compile. Not copied and not mutated.

    		 required

    Returns:

    Name Type Description
    A CompiledCircuit

    class:~mimiqcircuits.backends.CompiledCircuit whose source
    CompiledCircuit

    is the circuit with its containers expanded.

    Examples:

    >>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> c = mc.Circuit()
>>> _ = c.push(mc.GateH(), 0)
>>> compiled = TkSimulator().compile(c)
>>> len(list(compiled.source))
1

    evolve(state, compiled, *, rng=None, callback=None, stopped=None) ¶

    Evolve state in place under compiled.

    The main loop. Each instruction is routed by _apply_instruction to the classical register, the Clifford frame, or the MPS.

    The second return value is the accuracy claim for the run, and its type carries information the number does not:

    • :class:~mimiqcircuits.backends.ExactFidelity: the bonddim cap never bound. Before each operation that can grow a bond, the bonds had room to grow by that operation's full factor. Weight dropped below sv_cutoff does not count against it: that is the requested tolerance. A pure Clifford circuit always reports this.
    • :class:~mimiqcircuits.backends.TruncationLowerBound: the cap bound at least once, and the fidelity is at least the reported value, the weight that survived.

    TruncationLowerBound(1.0) is deliberately not ExactFidelity. The claim is about what could have been cut, not about what happened to be: an operation that reached the cap weakens the claim even if it discarded nothing.

    Parameters:

    Name Type Description Default
    state TkState

    A :class:.TkState, mutated in place and also returned. It is not reset first, so evolving twice composes the two circuits.

    		 required
    compiled CompiledCircuit

    The artifact from :meth:compile.

    		 required
    rng Optional[Random]

    A :class:random.Random that decides measurements, resets and noise. The call advances it by one draw, which reseeds the core, so two calls sharing one generator draw independent numbers and two generators built from the same seed give the same run. None (default) continues the core's own stream, which starts from operating-system entropy, so the run is not reproducible.

    		 None
    callback Optional[Callable[..., object]]

    Invoked once per instruction as callback(i, total) with a 1-based i, the contract progress.execution_progress_callback documents. Swallowing it leaves progress=True bars frozen.

    		 None
    stopped Optional[object]

    An object with a value attribute; evolution breaks out of the loop as soon as it turns truthy. Used for cooperative cancellation from another thread. A run stopped this way still returns the fidelity accumulated so far.

    		 None

    Returns:

    Type Description
    TkState

    The (state, fidelity) pair: the same state object that was
    Fidelity

    passed in, and the accuracy claim described above.

    Raises:

    Type Description
    NotImplementedError

    If an instruction is one this backend cannot execute, such as a Kraus channel that is not a Pauli mixture. :meth:can_handle rejects the known cases up front, which is the cheaper place to find out.
    ValueError

    If an IfStatement carries fewer classical bits than its condition needs, or if the core refuses an argument (a malformed gate matrix or Pauli string).
    IndexError

    If an instruction addresses a qubit outside state.

    Examples:

    A Clifford circuit is exact, because the MPS is never touched:

>>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> sim = TkSimulator()
>>> c = mc.Circuit()
>>> _ = c.push(mc.GateH(), 0)
>>> _ = c.push(mc.GateCX(), 0, 1)
>>> state, fidelity = sim.evolve(sim.build_state(2), sim.compile(c))
>>> type(fidelity).__name__
'ExactFidelity'

Counting the instructions through the callback:

>>> seen = []
>>> _ = sim.evolve(sim.build_state(2), sim.compile(c),
...                callback=lambda i, total: seen.append((i, total)))
>>> seen
[(1, 2), (2, 2)]

    expectation(state, op, *qubits) ¶

    Return <psi|op|psi> on state, without changing it.

    Exact: nothing is sampled, and the value is that of the state as evolved, truncation included. op is conjugated through the Clifford frame rather than applied to the state, so a :class:~mimiqcircuits.PauliString costs one MPS inner product however many qubits it spans, and any other operator on m qubits costs 4**m.

    state TkState

    A :class:.TkState built by this simulator.

    		 required
    op

    A :class:~mimiqcircuits.PauliString, or any operator with a matrix, such as a gate.

    		 required
    *qubits int

    The 0-based qubits op acts on, in its own leg order, one per qubit of op.

    		 ()

    Returns:

    Type Description
    complex

    The complex expectation value.

    Raises:

    Type Description
    ValueError

    If the number of qubits does not match op.

    Examples:

    >>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> sim = TkSimulator()

    simplify_pass() ¶

    The pass execute(simplify=True) installs.

    The default pass also resynthesizes gate runs into GateU and GateCX. A GateU is not recognized as a Clifford even at Clifford angles, so it would move gates the frame absorbs for free onto the MPS. This keeps only the passes that never change gate types: removing identities, cancelling inverse pairs and merging rotations, which turns T T into S and so moves gates into the frame.

    Returns:

    Name Type Description
    A

    class:~mimiqcircuits.SimplifyPass.

    Examples:

    Two ``T`` gates merge into an ``S``, which the frame absorbs:

>>> import mimiqcircuits as mc
>>> from mimiqcircuits.backends.passes import PassContext
>>> from tensorkeeper import TkSimulator
>>> c = mc.Circuit()
>>> _ = c.push(mc.GateT(), 0)
>>> _ = c.push(mc.GateT(), 0)
>>> _ = c.push(mc.GateH(), 0)
>>> simplified, _ = TkSimulator().simplify_pass().apply(PassContext(), c)
>>> [type(i.operation).__name__ for i in simplified]
['GateS', 'GateH']

    recompile_per_trajectory(circuit) ¶

    Whether each trajectory needs its own compile.

    Always False. Mixed-unitary noise is resolved by sampling a Pauli into the Clifford frame at runtime, inside :meth:evolve, rather than by baking a chosen branch into the compiled artifact, so one compile serves every shot and the driver can hoist it out of the trajectory loop.

    Parameters:

    Name Type Description Default
    circuit Circuit

    The circuit about to be run. Ignored; the answer does not depend on its contents.

    		 required

    Returns:

    Type Description
    bool

    False.

    Examples:

    >>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> c = mc.Circuit()
>>> _ = c.push(mc.Depolarizing1(0.1), 0)
>>> TkSimulator().recompile_per_trajectory(c)
False

    GPU simulator¶

    TkSimulatorGpu is TkSimulator with the residual MPS on an NVIDIA GPU: same arguments, same capabilities, same results. Check gpu_available first.

    tensorkeeper.TkSimulatorGpu ¶

    Bases: TkSimulator

    Clifford-augmented MPS simulator with the residual MPS on an NVIDIA GPU.

    The same simulator as :class:~tensorkeeper.TkSimulator, with the same arguments, capabilities and results. Every state it builds keeps its residual MPS |phi> in device memory for the whole run: through evolution, sampling, and the resets between shots. The Clifford frame stays on the host, since a frame update is a few word operations per qubit and never reads the MPS.

    When it pays. The device does the MPS work, so it helps when that work is large: a circuit with enough magic to push the bond dimension up. On a Clifford-dominated circuit whose residual stays small, the CPU simulator is as fast or faster, because there is little MPS work to move.

    Parameters:

    Name Type Description Default
    bonddim int

    As for :class:~tensorkeeper.TkSimulator.

    		 256
    sv_cutoff Optional[float]

    As for :class:~tensorkeeper.TkSimulator.

    		 None
    disentangle_period int | str

    As for :class:~tensorkeeper.TkSimulator.

    		 1
    max_num_threads Optional[int]

    As for :class:~tensorkeeper.TkSimulator.

    		 None
    linalg Optional[str]

    The host library under the device engine. The CUDA engine is built on OpenBLAS, so this must be None (default) or "openblas"; sim.linalg reads "openblas".

    		 None

    Raises:

    Type Description
    ValueError

    If bonddim is not positive, or linalg names a library other than OpenBLAS.
    RuntimeError

    If :func:tensorkeeper.gpu_available is False: this installation has no CUDA engine, or no device is reachable through it. The message says which, and what to install. Refused here rather than falling back to the CPU, so a run never reports GPU timings that were CPU ones.

    Examples:

    Pick the GPU when there is one:

>>> import tensorkeeper as tk
>>> sim = tk.TkSimulatorGpu() if tk.gpu_available() else tk.TkSimulator()
>>> sim.name in ("TensorKeeper", "TensorKeeperGpu")
True

    tensorkeeper.gpu_available() ¶

    Whether this process could use a GPU.

    True means this installation carries the CUDA engine and a device is reachable through it now. Every way of not having one (a CPU-only wheel, no driver, no CUDA libraries, no card) reports False, so this is safe to call anywhere and never raises. The first call probes for a device, which takes a moment when there is a CUDA engine to probe with.

    :class:TkSimulatorGpu requires this to be True.

    Returns:

    Type Description
    bool

    True if a GPU is usable by the core, False otherwise.

    State¶

    tensorkeeper.TkState ¶

    Bases: State

    A CAMPS state plus the classical and complex registers.

    The quantum register is the Clifford frame and MPS pair held in the Rust core, reached through :attr:core. The classical bits are a :class:~mimiqcircuits.BitString and the z-variables a list of complex numbers, both of which the MIMIQ driver writes into directly and then copies into results.cstates / results.zstates.

    You rarely construct one of these. :meth:.TkSimulator.build_state does it for you, and execute does that in turn. Building one by hand is worth it when you want to evolve a circuit and then interrogate the resulting state repeatedly: :meth:amplitude, :meth:probability and the expectation values are all non-destructive, so a single evolution can answer many questions.

    Examples:

    Build a two-qubit state, evolve a Bell pair onto it, and read the
result back three different ways:

>>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> sim = TkSimulator()
>>> c = mc.Circuit()
>>> _ = c.push(mc.GateH(), 0)
>>> _ = c.push(mc.GateCX(), 0, 1)
>>> state = sim.build_state(2)
>>> state, _ = sim.evolve(state, sim.compile(c))
>>> round(state.probability(mc.BitString("00")), 6)
0.5
>>> round(state.expectation_paulistring("ZZ", [0, 1]).real, 6)
1.0
>>> state.bond_dim
1

The last line is what the simulator buys: a Bell pair is entangled, but
it is a *stabilizer* state, so all of its entanglement sits in the
Clifford frame and the residual MPS is still a product state at
``chi = 1``.

    core property ¶

    The underlying Rust CAMPS state.

    The escape hatch for primitives this class does not wrap: the per-bond profile from core.bond_dims(), the raw Clifford application in core.apply_clifford(code, qubits), and so on. Nothing on it is part of the stable Python API; prefer the methods on this class where they exist.

    classical_bits property ¶

    The classical bit register, as a live mutable bitstring.

    Measurements write here, the classical-logic operations (Not, Xor, …) read and write here, and IfStatement conditions are evaluated against it. The driver copies this object into results.cstates once per trajectory.

    complex_values property ¶

    The complex z-register, as a live mutable list.

    ExpectationValue, Amplitude and BondDim write their results here; Add, Multiply and Pow do arithmetic on it. The driver copies it into results.zstates.

    bond_dim property ¶

    The largest MPS bond dimension currently in use.

    This is a property of the residual |phi>, not of the physical state |psi>. Entanglement carried by the Clifford frame is invisible to it, so a maximally entangled stabilizer state reads back as 1. That is the useful number, since it is what the simulator actually stores and what :meth:.TkSimulator.limits caps, but it is not the state's Schmidt rank, and it must not be reported as an entanglement measure.

    Typically far below the cap: only nonstabilizerness reaches the MPS, so a Clifford-dominated circuit stays near 1 however deep it runs.

    Returns:

    Type Description
    int

    The largest bond dimension over all cuts of |phi>, at least
    int

Clifford, so the residual never leaves ``chi = 1``:

>>> import mimiqcircuits as mc

    to_device() ¶

    Move the residual MPS onto the GPU for the rest of the run.

    The Clifford frame stays on the host. It is a bit-packed tableau updated in O(n) word operations, so there is nothing for a GPU to do with it, and a Clifford gate never reads the MPS, so that path costs no transfer at all.

    Worth doing only if the state then stays there for a stretch of circuit: a round trip costs more than the work it would feed. Move once, evolve, read at the end. Reads are what to watch, since :meth:prob_bitstring and sampling walk the register on a copy.

    Raises:

    Type Description
    RuntimeError

    if this build has no GPU backend, if no device is reachable, or if the upload fails. Call :func:tensorkeeper.gpu_available to tell the first two apart from a transient failure.

    sample(nsamples, rng=None) ¶

    Sample nsamples computational-basis bitstrings.

    The state is not disturbed: each draw collapses a throwaway copy, so repeated calls are independent samples of the same state and every read-out method still works afterwards. This is what makes execute cheap on a purely unitary circuit, which evolves once and then samples.

    Parameters:

    Name Type Description Default
    nsamples int

    		 required
    rng Optional[Random]

    		 None

    list[BitString]

    reset() ¶

    Reset every register to its zero value, reusing the allocation.

    This is what the driver calls between shots. The quantum register is rebuilt in the core rather than reset qubit by qubit: the latter leaves the Clifford frame in place and the accumulated fidelity untouched, which across shots would charge later shots for an earlier shot's truncation.

    The configuration and the RNG stream survive, so consecutive shots stay distinct.

    Examples:

    >>> import mimiqcircuits as mc
>>> from tensorkeeper import TkSimulator
>>> sim = TkSimulator()
>>> c = mc.Circuit()
>>> _ = c.push(mc.GateH(), 0)
>>> _ = c.push(mc.GateCX(), 0, 1)
>>> _ = c.push(mc.GateT(), 1)
>>> state, _ = sim.evolve(sim.build_state(2), sim.compile(c))
>>> state.reset()
>>> round(state.probability(mc.BitString("00")), 6)
1.0

    Capabilities¶

    tensorkeeper.TARGET_CAPABILITIES = frozenset({'amplitude', 'sampling', 'classical_bits', 'zvars', 'midcircuit_measure', 'midcircuit_reset', 'reset_after_measure', 'feed_forward', 'noise', 'bond_dim', 'expectation_1q', 'expectation_2q', 'expectation_paulistring', 'expectation_state'}) module-attribute ¶

    The capability set TensorKeeper is being built towards.

    A MIMIQ capability is a promise: declaring one commits the backend to executing every operation that belongs to it. This literal records the intended final set so it can be read as a roadmap, and so a conformance test can check the whole set against :data:~mimiqcircuits.backends.CAPABILITY_VOCABULARY rather than only the part that works today.

    Every entry is also implemented today, so what :meth:TkSimulator.capabilities returns is equal to this, but the two stay separate literals on purpose. The comment above the assignment says why an over-declaration is the dangerous direction.

    Every capability below is declared and executes. Anything absent is refused, by can_handle where it can be detected before the run starts.

    Capability Instruction it enables
    amplitude Amplitude
    sampling sampling from the final state
    classical_bits Not, And, Or, Xor, SetBit0, SetBit1, ReadoutErr
    zvars Add, Multiply, Pow
    midcircuit_measure Measure, MeasureX, MeasureY, MeasureXX, MeasureYY, MeasureZZ, MeasurePauli
    midcircuit_reset Reset, ResetX, ResetY, PrepareStateT
    reset_after_measure MeasureReset, MeasureResetX, MeasureResetY
    feed_forward IfStatement
    noise mixed-unitary (Pauli) Kraus channels only
    bond_dim BondDim
    expectation_1q ExpectationValue of a 1-qubit operator
    expectation_2q ExpectationValue of a 2-qubit operator
    expectation_paulistring ExpectationValue of a PauliString

    Not supported, and declined by can_handle: SchmidtRank, VonNeumannEntropy, WhileStatement, and any non-mixed-unitary Kraus channel.

    Fidelity¶

    evolve returns (state, fidelity), where the fidelity is one of mimiqcircuits.backends' two types:

    Type Meaning
    ExactFidelity() the bonddim cap never bound; weight below sv_cutoff is the requested tolerance
    TruncationLowerBound(v) the cap bound at least once; the fidelity is at least v

    Once the cap has bound, the claim is TruncationLowerBound and never ExactFidelity, and TruncationLowerBound(1.0) is deliberately not ExactFidelity(). See Accuracy and Tuning.

    tensorkeeper.qiskit.TensorKeeperEstimator ¶

    Bases: BaseEstimatorV2

    Qiskit EstimatorV2 backed by the TensorKeeper CAMPS simulator.

    On a circuit that ends in a definite state, results are exact up to the MPS truncation set by tk_options: no term is sampled, whatever its weight, so the reported standard errors are zero and the only error left is the truncation, reported as min_fidelity in the result metadata.

    A circuit carrying a mid-circuit measurement, a reset or a noise channel ends in an ensemble, and its expectation value is the average over the trajectories TensorKeeper evolves, one per shot. That average is the unbiased estimate of :math:\mathrm{Tr}(\rho O), so it is what this reports, with the sample standard error in stds. Reading one trajectory would be unbiased too but as noisy as the observable's own range, so a stochastic circuit with no budget raises rather than returning it.

    Parameters:

    Name Type Description Default
    simulator

    An existing TensorKeeper simulator to use as is, in which case tk_options must be empty and gpu and mock false. None (default) builds one from them.

    		 None
    gpu bool

    Evaluate on :class:~tensorkeeper.TkSimulatorGpu, with the residual MPS on an NVIDIA GPU. Default False.

    		 False
    mock bool

    Evaluate on :class:~tensorkeeper.MockTensorKeeper instead. It takes the same options and refuses the same inputs, needs no licence, and simulates nothing: every expectation value is 0. For tests of the plumbing around a backend; see the "Without a licence" page of the manual. Default False.

    		 False
    method str

    "auto" (default) evaluates exactly when the circuit is deterministic and averages trajectories when it is not. "exact", "trajectories" and "shots" force one of the three, as documented in :mod:mimiq_qiskit.estimation.

    		 'auto'
    trajectories int | None

    Trajectories to average for a stochastic circuit. None sizes it from precision. Ignored for a deterministic circuit, which has one answer however many times it is run.

    		 None
    shots int | None

    Shots per measurement basis, estimating from measurements in rotated Pauli bases the way hardware and Qiskit's BackendEstimatorV2 do. Giving this selects that method. For a given budget it is noisier than averaging trajectories, since it samples the observable as well as the ensemble; it is the right choice for reproducing a shot-based reference.

    		 None
    emulate_shot_noise bool

    Add Gaussian noise of width precision to an otherwise exact value, as Qiskit's StatevectorEstimator does. One evolution rather than a shot budget, for code that wants to see plausible shot noise without paying for it.

    		 False
    default_precision float

    Precision used when run is called without one. A positive value sizes the trajectory or shot budget as ceil(1/precision**2), Qiskit's convention. The default, 0.0, asks for the exact value.

    		 0.0
    seed int | None

    Seed forwarded to every run, and to the emulate_shot_noise generator. Expectation values consume no randomness, so it only matters for a circuit that carries noise or mid-circuit measurements. None (default) draws fresh entropy.

    		 None
    **tk_options

    Options of the simulator, fixed at construction: bonddim, sv_cutoff, disentangle_period, max_num_threads and linalg, as :class:~tensorkeeper.TkSimulator describes them. An option it does not take raises :class:TypeError.

    		 {}

    Result metadata reports method, whether the value is exact, whether the run was stochastic, the trajectories or shots spent, the target_precision, and min_fidelity: the lowest MPS fidelity behind the pub. That last one is the truncation error, which averaging more trajectories does not reduce; raise bonddim for that.

    default_precision property ¶

    Precision used when run is called without an explicit one.

    run(pubs, *, precision=None) ¶

    Estimate every pub and return the job carrying the results.

    precision overrides :attr:default_precision for this call. It is recorded in the result metadata as target_precision, and where a budget is needed and none was given explicitly, a positive value sizes it as ceil(1/precision**2).
